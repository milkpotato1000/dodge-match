# 점수와 플레이어 경쟁

- 작성일: 2026-09-16
- 상태: 사용자 방향 반영 / 초기 밸런스 제안
- 관련 규칙: [동시 플레이 게임 기획](gameplay.md)

## 경쟁 방식

첫 경쟁 기능은 같은 경기를 동시에 연결하는 실시간 대전보다 비동기 리더보드를 우선한다. 각 플레이어가 혼자 한 판을 플레이하고, 입력한 이름과 최종 점수를 순위표에서 비교한다. 첫 구현은 로컬 순위표이며 온라인 순위표는 핵심 플레이 QA 이후 추가한다.

이 방식은 핵심 게임을 먼저 검증할 수 있고 네트워크 지연이 회피·타이밍 판정에 영향을 주지 않는다. 실시간 대전, 친구 초대와 시즌은 후속 범위로 둔다.

## 점수 융합 제안

최종 점수는 `회피 생존 점수 + Match 판정 점수`로 계산한다. 결과 화면과 리더보드에는 최종 점수뿐 아니라 두 구성 점수도 함께 표시한다.

### 회피 생존 점수

`회피 생존 점수 = 생존한 온전한 1초 × 100점`

- 내부적으로 생존 시간은 밀리초로 기록하되 점수는 완료한 초 단위로 계산한다.
- 한 판이 끝나기 직전의 완료되지 않은 1초는 생존 기록에는 표시하지만 점수에는 넣지 않는다.

### Match 판정 점수

| 판정 | 기본 점수 |
| --- | ---: |
| `Perfect` | 100 |
| `Great` | 70 |
| `Good` | 40 |
| `Miss` | 0 |
| 금지색 원을 누르지 않음 | `Perfect`와 동일 |

- 금지색 원을 판정 구간 동안 누르지 않으면 `Perfect`로 처리하여 기본점수, 점수 콤보와 생명 회복을 모두 동일하게 적용한다.
- 금지색 원을 누르면 `Miss(금지색)`로 기록하며 Match 점수는 0점이고 Match 생명이 감소한다.
- `Good`, `Great`, `Perfect`는 모두 점수 콤보를 1 올리고 `Miss`는 점수 콤보를 0으로 초기화한다.
- 점수 콤보는 생명 회복 콤보와 별개다. `Good`은 점수 콤보를 이어 점수 이득을 받지만 생명을 회복하지 않으며 생명 회복 콤보는 끊는다.

### 점수 콤보 배율

판정으로 콤보를 올린 뒤, 새 콤보 수에 해당하는 배율을 현재 판정의 기본점수에 곱한다. 소수점은 가장 가까운 정수로 반올림한다.

| 현재 점수 콤보 | 배율 |
| ---: | ---: |
| 1~9 | ×1.00 |
| 10~24 | ×1.10 |
| 25~49 | ×1.25 |
| 50~99 | ×1.50 |
| 100 이상 | ×2.00 |

같은 콤보라면 항상 `Good < Great < Perfect` 순으로 기본점수와 콤보 보너스가 커진다. 예를 들어 100 콤보 이상에서는 `Good 80점`, `Great 140점`, `Perfect 200점`이다.

### 만점

첫 차트는 120 BPM, 180초이며 곡 길이, BPM과 판정 대상 수가 고정되어 있으므로 이론상 만점이 존재한다. 색과 위치가 무작위여도 모든 원은 판정을 하나 만들고, 금지색 원의 올바른 미터치가 `Perfect`이므로 만점은 변하지 않는다.

`차트 만점 = 곡 전체 생존 점수 + 모든 판정이 Perfect일 때 콤보 배율을 순서대로 적용한 Match 점수`

차트 제작 시 이 값을 미리 계산해 `max_score`로 저장한다. 결과 화면에는 `획득 점수 / 차트 만점`과 달성률을 표시한다. 첫 10개 판정이 모두 `Perfect`라면 1~9번째는 각 100점, 10번째는 콤보 배율 ×1.10이 적용된 110점으로 합계 1,010점이다.

첫 180초 차트에는 판정 대상이 151개 있다. 색 전환 직전 0.5초 생성 금지 규칙을 제거해 이전보다 11개 늘었다. 전부 `Perfect`일 때 Match 만점은 23,575점, 180초 생존 점수는 18,000점이므로 **총 만점은 41,575점**이다.

원 생성은 박자 격자에서 빨라지지만 차트마다 대상 수가 고정된다. 밸런스 테스트에서는 같은 생존 시간일 때 Match 실력으로 순위가 갈리고, 높은 Match 정확도만으로 짧은 생존 시간을 완전히 만회하기는 어렵게 계수를 조정한다.

동점이면 생존 시간 → `Perfect` 수 → `Miss`가 적은 순 → 먼저 기록된 점수 순으로 정렬하는 안을 사용한다.

## 로컬 기록과 온라인 DB

플레이어 이름과 점수를 현재 기기에만 저장하는 로컬 순위표에는 온라인 DB가 필요 없다. 다른 플레이어와 인터넷으로 순위를 비교하려면 공유 DB와 점수 제출 API가 필요하다. 사용자가 DB를 직접 처음부터 구축해야 하는 것은 아니며, 개발 단계에서 관리형 백엔드 서비스를 선택할 수 있다.

권장 단계는 다음과 같다.

1. 로컬 최고 기록으로 점수와 난이도를 검증한다.
2. 규칙이 안정되면 관리형 백엔드 기반 온라인 리더보드를 추가한다.
3. 실제 경쟁성이 중요해지면 서버 검증과 부정 점수 방지를 강화한다.

## 리더보드 데이터 초안

표시 이름만으로 플레이어를 식별하지 않는다. 이름 중복을 허용하고 내부 플레이어 ID와 한 판 ID를 별도로 생성한다.

| 필드 | 목적 |
| --- | --- |
| `run_id` | 한 판을 구분하는 고유 ID |
| `player_id` | 익명 계정 또는 기기 기반 내부 ID |
| `player_name` | 순위표에 표시할 이름 |
| `total_score` | 최종 합산 점수 |
| `survival_ms` | 실제 생존 시간 |
| `dodge_score` | 생존 시간으로 얻은 점수 |
| `match_score` | 타이밍 판정으로 얻은 점수 |
| `chart_id` | 곡과 판정 시점 구성을 식별하는 ID |
| `max_score` | 해당 차트·규칙 버전의 이론상 만점 |
| `rng_seed` | 해당 판의 색·Match 위치·Dodge 점 생성 초기조건을 재현하는 시드 |
| `result` | `clear`, `dodge_collision`, `match_depleted` |
| `perfect/great/good/miss` | 판정별 횟수 |
| `max_score_combo` | 최대 점수 콤보 |
| `max_recovery_combo` | `Great/Perfect` 최대 연속 횟수 |
| `max_miss_streak` | 최대 연속 `Miss` 횟수 |
| `ruleset_version` | 서로 다른 밸런스 버전의 기록 분리 |
| `created_at` | 기록 시각 |

플레이어 이름에는 길이 제한과 금칙어 처리가 필요하다. 초기 제안은 공백 제거 후 1~16자이며, 중복 이름은 허용한다.

## 순위표 제안

- 전체 최고 기록과 오늘/이번 주 기록을 분리한다.
- 상위 100명, 내 최고 기록과 내 주변 순위를 보여준다.
- 점수와 함께 생존 시간 및 `Perfect / Great / Good / Miss` 요약을 표시한다.
- 밸런스나 판정 기준이 바뀌면 `ruleset_version`별로 순위를 분리한다.
- 색, Match 위치와 Dodge 점 생성 초기조건은 판마다 달라도 허용한다. 이후 점 궤적은 물리 규칙으로 계산하며, 제출된 난수 시드를 함께 저장해 해당 판을 재현할 수 있게 한다.
- 초기 온라인 버전은 클라이언트가 제출한 점수를 저장할 수 있지만 조작 가능성이 있다. 공개 경쟁으로 발전시키려면 서버가 한 판의 지속 시간과 판정 집계를 검증해야 한다.

## 남은 결정

- 생명 회복·감소 수치의 플레이 테스트 조정
- 점수 콤보 배율 구간과 기본점수의 플레이 테스트 조정
- 게스트 이름만 받을지 로그인·닉네임을 지원할지
- 온라인 순위표를 추가할 시점과 백엔드 서비스
- 온라인 기록의 보존 기간, 이름 신고·삭제 정책과 부정 기록 처리
