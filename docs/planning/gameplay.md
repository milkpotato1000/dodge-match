# 동시 플레이 게임 기획

- 작성일: 2026-09-16
- 상태: 첫 구현 기준선. 표시된 수치는 플레이 테스트 후 조정할 수 있다.
- 화면 명칭: 가로 화면 기준으로 Dodge 영역과 Match 영역이라 부른다.

## 1. 핵심 경험과 화면

플레이어는 방향 버튼 또는 키보드로 캐릭터를 움직여 점을 피하는 동시에, Match 영역 원의 색과 링의 수축을 보고 누를 원과 누르지 않을 원을 구분한다. 두 게임은 동시에 진행한다. 캐릭터가 다른 색 구역으로 이동하면 금지색도 바뀐다.

모바일과 PC 모두 가로 화면을 사용한다. 두 게임 영역은 중앙 구분선을 기준으로 50:50으로 나눈다.

- 기본 배치는 `Dodge 왼쪽 / Match 오른쪽`이다. 오른손으로 타이밍 입력을 하기 쉬운 배치다.
- 시작 전 설정에서 `Match 왼쪽 / Dodge 오른쪽`으로 교환할 수 있다. 한 판 도중에는 교환하지 않는다.
- 모바일에서는 Dodge 영역 하단 모서리의 고정 D-pad를 한 손가락으로 누르고 Match 영역의 다른 손가락을 판정 입력으로 사용한다.
- PC에서는 설정에서 선택한 `WASD` 또는 `방향키`로 Dodge 캐릭터를 움직이고 마우스로 Match 원을 누른다.
- 세로 방향으로 실행하면 회전 안내를 보여주고 플레이를 시작하지 않는다.

## 2. 회피 게임

### 요구사항

- 캐릭터는 Dodge 영역 중앙에서 시작한다.
- 모바일에서는 Dodge 영역의 고정 4방향 D-pad로 상하좌우와 대각선 4방향을 입력한다.
- 초기에는 소량의 야구공이 Dodge 영역 안에서 이동하며 벽에 튕긴다.
- 시간에 따라 야구공의 수와 속도가 점진적으로 증가한다. 각각 최대 제한이 있다.
- 캐릭터가 야구공에 닿지 않도록 피한다. 충돌 영역은 기획에서 설정할 수 있다.

### 조작·충돌 제안

- D-pad는 Dodge가 왼쪽이면 Dodge 좌하단, Dodge가 오른쪽이면 Dodge 우하단의 **화면 바깥쪽 모서리**에 자동 배치한다. 한 판 도중에는 위치가 바뀌지 않는다.
- 화면에는 상·하·좌·우 네 버튼을 십자 형태로 표시한다. 버튼 묶음은 112dp 정사각형, 각 방향의 최소 터치 영역은 44×44dp, 화면 가장자리 여백은 16dp를 첫 기준으로 한다.
- 방향 버튼은 이동량을 조절하지 않는다. 한 방향 이상을 누르는 동안 캐릭터는 항상 90U/s로 움직이고, 모두 놓으면 즉시 정지한다.
- 인접한 두 방향을 함께 누르면 대각선으로 이동한다. 대각선 벡터를 정규화하여 가로·세로 이동과 같은 90U/s를 유지한다. 서로 반대인 좌우 또는 상하 입력은 해당 축에서 서로 상쇄한다.
- 한 손가락으로 버튼 사이를 미끄러지듯 이동할 수 있다. 네 버튼이 공유하는 터치 영역은 손가락의 중심 방향을 8방향으로 양자화하며, 버튼 사이 대각 구간에서는 인접한 두 버튼을 동시에 누른 것으로 처리한다. 입력 세기는 항상 0 또는 1이다.
- D-pad에서 시작한 포인터는 이동 전용으로 고정하고, Match 영역에서 시작한 다른 포인터들은 판정 입력으로 고정한다. 포인터가 영역을 가로질러도 역할이 바뀌지 않는다.
- D-pad 포인터를 떼거나 공유 터치 영역 밖으로 옮기면 캐릭터는 정지하고 두 게임은 계속 진행한다. Dodge 영역의 다른 위치를 누르거나 드래그해도 캐릭터는 움직이지 않는다.
- PC 설정에 `이동 키`를 두고 `WASD`와 `방향키` 중 하나를 선택한다. 기본값은 `WASD`이며 선택은 기기에 저장한다. 시작 설정과 일시정지 설정에서 바꿀 수 있다.
- 선택한 키 묶음만 이동 입력으로 사용한다. `WASD` 선택 중 방향키를 누르거나 `방향키` 선택 중 WASD를 눌러도 캐릭터는 움직이지 않는다.
- 두 키 묶음은 같은 8방향 벡터, 90U/s 속도와 반대 입력 상쇄 규칙을 사용한다. 설정을 바꾸는 순간 기존 키 눌림 상태를 모두 해제하고 이동 벡터를 0으로 초기화해 키가 고정되는 현상을 막는다.
- 캐릭터 전체가 회피 영역 밖으로 나가지 않도록 제한한다.
- 충돌은 원형으로 판정한다. 캐릭터 충돌 반지름은 1.5U, 야구공은 표시 반지름과 같은 1.6U다. 중심 거리 ≤ 판정 반지름의 합이면 충돌한다.
- 회피 오브젝트의 시각 자산은 아이보리 몸체와 남청·회색 봉제선을 가진 야구공이다. 봉제선 방향과 렌더 회전은 장식이며 원형 충돌 범위, 이동 벡터와 반사각을 바꾸지 않는다.
- 캐릭터 충돌 원의 중심은 상태별 이미지의 공통 바닥 피벗에 고정한다. `idle`, 이동, 기울기, 호흡, `near-hit`, 성공, 울음과 피격 모션이 그림의 크기·자세·회전·투명도를 바꿔도 충돌 중심과 1.5U 반지름은 바뀌지 않는다.
- 새 야구공과 초기 야구공은 캐릭터에 겹쳐 생성하지 않는다. 새 야구공은 경계에서 0.5초 예고한 뒤 활성화하며, 활성화 순간 캐릭터 중심에서 최소 15U 떨어져야 한다.
- 야구공은 네 색 구역을 합친 Dodge 전체 큰 사각형 안을 제한 없이 가로질러 이동한다. 중앙의 가로·세로 색 경계와 0.125U 십자 헤어라인은 물리 벽이 아니며 통과할 때 방향·속도가 변하지 않는다.
- 야구공끼리는 충돌하지 않고 서로 통과한다. Dodge **최외곽 사각 벽에서만** 입사각과 반사각이 같도록 정반사한다. 수평 벽은 속도의 세로 성분만, 수직 벽은 가로 성분만 반전하며 모서리에 동시에 닿으면 두 성분을 모두 반전한다. 반사 전후의 속력은 같다.
- 캐릭터와 야구공의 충돌이 발생하는 순간 전체 게임을 즉시 종료한다.

야구공의 **생성 초기조건만** 판마다 무작위다. 초기 야구공의 위치·최초 진행각과 추가 야구공의 경계 등장 위치·최초 안쪽 진행각을 하나의 `rng_seed`에서 추첨한다. 초기 야구공은 전체 사각형의 합법 영역에서 고르게 뽑고, 추가 야구공은 네 변을 합친 외곽 둘레 길이에 비례해 등장 지점을 뽑는다. 추가 야구공의 각도는 안쪽 법선에서 좌우 20°~70° 범위로 제한해 벽과 거의 나란히 붙거나 같은 축만 반복하는 궤적을 줄인다. 모서리 4U 이내, 캐릭터 15U 이내와 다른 활성 야구공에 겹치는 후보는 재추첨한다.

야구공이 활성화된 뒤의 비행과 충돌에는 난수를 사용하지 않는다. 야구공은 정해진 속도로 직진하고, 외곽 벽의 법선 벡터를 `n`, 충돌 직전 속도를 `v`라 할 때 `v' = v - 2(v·n)n`으로 반사한다. 임의 방향 전환, 각도 흔들림, 캐릭터 추적과 순간 이동은 없다. 같은 초기조건에서는 언제나 같은 궤적이 나오며, 같은 규칙 버전과 시드를 다시 사용하면 모든 야구공의 생성과 이동이 동일하게 재현된다.

`U`는 Dodge 영역의 짧은 변 길이를 100으로 본 정규화 단위다. 캐릭터 표시 반지름은 2U, 충돌 반지름은 1.5U, 야구공의 표시·충돌 반지름은 1.6U로 시작한다. 캐릭터 최대 이동 속도는 90U/s다. 캐릭터 그림은 최초 3U 안보다 약 33% 작고, 충돌 원은 표시 반지름의 75%로 고정한다.

| 경과 시간 | 목표 야구공 개수 | 야구공 속도 |
| ---: | ---: | ---: |
| 0초 | 3 | 18U/s |
| 30초 | 6 | 22U/s |
| 60초 | 10 | 28U/s |
| 90초 | 15 | 36U/s |
| 120초 | 22 | 46U/s |
| 150초 | 28 | 58U/s |
| 165초 이후 | 최대 32 | 최대 65U/s |

두 기준점 사이의 속도는 선형으로 증가한다. 야구공은 목표 개수에 도달하도록 해당 구간에 균등하게 추가한다. 0~60초는 적응 구간, 60~120초는 중간 난이도, 120~165초는 어려운 구간, 마지막 15초는 극난도 구간이다.

### Dodge 난이도 상향 결정

- 2026-09-16 디자인 리뷰에서 기존 3→22개 곡선의 화면 밀도와 회피 압박이 부족하다고 판단해 첫 구현 기준선을 **3→32개**로 올렸다.
- 야구공 개수는 `0/30/60/90/120/150/165초 = 3/6/10/15/22/28/32개`로 증가한다. 최대 속도는 65U/s로 유지해 개수와 속도를 한 번에 모두 크게 올리지 않는다.
- 시안 v16의 `02:23.456` 장면은 약 26개 야구공으로 120~150초 구간의 상향된 시각 밀도, 더 작아진 강아지와 금지색 오입력 뒤 한 칸만 분리된 상태를 보여준다.
- 상향된 기준에서도 새 야구공의 0.5초 예고, 캐릭터 중심 15U 안전 거리, 최대 동시 야구공 수 상한과 60fps 유지 조건은 지킨다.
- 첫 조작 테스트에서는 시각별 생존율, 통과 가능한 경로 폭과 피격 원인 판독성을 확인한다. 조정이 필요하면 32개 상한보다 먼저 90~150초 구간의 추가 시점을 조절한다.

## 3. 회피 영역의 색

### 요구사항

색 후보는 빨강·주황·노랑·초록·파랑·남색·보라의 7종이다.

| 단계 | 구역 구성 | 색 선택 | 진입 시점 |
| --- | --- | --- | --- |
| 1 | 전체 단색 | 7색 중 독립 무작위 | 0~15초 |
| 2 | 좌 / 우 | 구역마다 독립 무작위 | 15~30초 |
| 3 | 위쪽 좌 / 위쪽 우 / 아래쪽 전체 | 구역마다 독립 무작위 | 30~45초 |
| 4 | 상단 좌 / 상단 우 / 하단 좌 / 하단 우 | 구역마다 독립 무작위 | 45초 이후 |
| 4 이후 반복 | 사분면 유지 | 칸별 `nextColorChangeAt` 도달 시 무작위 재배정; 최초 시각은 모두 50.300초 | 50.300초부터 곡 종료까지 |

정기 색 전환 추첨은 빨강·주황·노랑·초록·파랑·남색·보라에서 동일 확률로 수행한다. 직전 색과 같은 색이 다시 나오거나 여러 구역이 같은 색이 되는 것을 허용한다.

### 금지색 터치 페널티 재추첨

- Match 원은 T−200ms에 금지 상태와 함께 그 원을 금지로 만든 Dodge `lockedZoneId`를 저장한다. 금지 원을 터치해 `Miss(FORBIDDEN)`이 확정되면 **그 칸 하나만** 같은 60Hz 시뮬레이션 스텝에서 즉시 재추첨한다. 클릭 시점에 캐릭터가 다른 칸으로 이동했어도 저장된 칸을 사용한다.
- 해당 칸은 자기 직전 색을 제외한 나머지 6색에서 동일 확률로 뽑는다. 다른 칸과 같은 새 색이 되는 중복은 허용한다.
- 해당 칸의 바닥 Match 문양도 새 색과 같은 스텝에 교체한다. 그 칸이 현재 캐릭터 위치라면 조명·위 배지·HUD 금지색 칩도 즉시 갱신하고, 다른 칸이라면 현재 금지색 표시는 유지한다.
- 눌린 원의 `FORBIDDEN` 판정은 변경 전 잠금 상태로 먼저 확정한다. 페널티 재추첨 때문에 이미 잠긴 다른 원의 허용·금지 상태가 바뀌지 않으며, 아직 잠기지 않은 원만 자신의 T−200ms에 새 금지색을 읽는다.
- 모든 활성 칸은 독립적인 `nextColorChangeAt`을 가진다. 45초에 4색 단계가 시작될 때 네 칸 모두 `50.300초`를 가리키므로, 실수가 없다면 같은 순간에 바뀐다. 페널티가 발생한 칸만 `nextColorChangeAt = forbiddenTapAt + 5.300초`로 재설정되어 동시 일정에서 빠지고, 이후 자기 시각마다 5.300초를 더해 독립적으로 바뀐다. 다른 칸의 시계는 건드리지 않는다.
- 같은 칸에서 다시 `Miss(FORBIDDEN)`이 발생하면 그 칸만 즉시 다시 뽑고 다음 변경 시각을 새 터치 시각+5.300초로 다시 시작한다. 다른 칸도 각자 한 번 틀리면 같은 방식으로 독립 일정이 된다.
- 15·30·45초의 구역 구조 전환에서는 새 구역 구조를 우선 적용하고 새로 생긴 모든 칸의 시계를 다음 정기 기준에 다시 맞춘다. 같은 스텝의 페널티는 구조 전환 뒤 `lockedZoneId`가 가리키던 위치를 포함하는 새 칸 하나에 적용해 그 칸만 다시 분리한다.
- 페널티 즉시 재추첨에는 3초 예고를 적용하지 않는다. 기존 원·야구공·캐릭터 위치와 속도는 그대로 유지한다. 정기 구조·색 전환은 3초 전부터 예고하지만 어떤 색 전환도 Match 원 생성을 막지 않는다.
- 같은 시뮬레이션 스텝에 해당 칸의 정기 전환도 예정되어 있으면 정기 전환을 먼저 처리한 뒤 페널티 재추첨을 적용하고, 다음 변경 시각을 터치 시각+5.300초로 정한다.
- 이 분리는 금지색 오입력의 큰 패널티다. 실수 이후에는 네 칸이 한꺼번에 바뀌는 규칙성을 잃고, 분리된 칸의 전환까지 따로 추적해야 한다. 점수·Match 생명 페널티와 함께 후반 인지 부하도 즉시 높인다.

### 시간·위치 판정 제안

- 4색 단계 진입 시각은 T4=`45.000초`다. 모든 칸의 최초 반복 시각은 `50.300초`이며, 페널티가 없으면 `55.600초`, `60.900초`, …에도 함께 바뀐다. 페널티가 발생한 칸만 그 입력 시각을 기준으로 자기 5.300초 주기로 분리된다.
- 칸별 ‘색 변경까지’ 남은 시간을 소수점 세 자리로 상시 표시한다. 모든 시각이 같을 때는 하나의 `SHIFT ALL`, 하나라도 분리되면 현재 구역 구조와 같은 칸 배열의 개별 타이머를 표시한다.
- 구역 경계에는 총 폭 0.125U의 검은 십자형 헤어라인을 둔다. 1600×900 논리 화면에서는 약 1px이며, 중심선 양쪽 0.0625U만 차지한다. 이 선은 색 판정 위치를 보여주지만 이동과 충돌에는 영향을 주지 않는다.
- 구역색 판정점은 캐릭터 상태와 모션에 영향받지 않는 공통 바닥 피벗이다. 캐릭터 아래 조명 중심에 작은 청백색 점으로 정확한 위치를 항상 표시한다.
- 판정점이 헤어라인 밖에 있으면 점이 위치한 구역을 현재 색으로 사용한다. 판정점이 헤어라인 안에 있는 동안은 직전 구역을 유지하고, 반대편 헤어라인 가장자리를 완전히 벗어난 첫 고정 시뮬레이션 스텝에 새 구역으로 바꾼다.
- 세로선과 가로선의 교차점에서도 같은 규칙을 적용한다. 이전 구역 없이 정확히 경계에서 시작하면 마지막 이동 방향이 향하는 구역을 선택하고, 이동 방향도 없으면 오른쪽, 이어서 아래쪽을 우선한다.
- 구역색이 바뀌는 스텝에 캐릭터 아래 조명, 캐릭터 위 고유 기호 배지, 공통 HUD 칩과 해당 Dodge 바닥 각인을 같은 색·문양 매핑으로 함께 바꾼다. 4색 단계 이전 구조 전환은 100ms 표시 교차만 허용하고, 4색 단계 이후 재추첨은 아래의 1초 페이드 규칙을 사용한다.
- 공통 HUD의 금지색 칩도 같은 시점에 바뀐다. Match 원의 터치/금지 상태가 T−200ms에 잠길 때 캐릭터 조명을 한 번 밝게 해 어떤 색이 사용됐는지 알린다.

차트에 정의된 단계 전환과 동기 정기 변경은 3초 전부터 카운트다운을 표시한다. 전환 직전·직후에도 Match 원은 차트대로 계속 등장하며, 입력으로 분리된 칸의 5.300초 타이머도 원 생성에 영향을 주지 않는다.

### 4색 이후 1초 재추첨 페이드

- 4색 단계 이후 정기·개별 타이머 재추첨은 총 1초의 `fade-out → fade-in`으로 표시한다. 정기 전환 시각을 T라 하면 T−0.500초부터 기존 바닥색과 문양을 선형으로 낮추고, T에서 논리 색을 새 값으로 교체한 뒤 T+0.500초까지 새 색과 문양을 선형으로 올린다.
- Match 원의 허용·금지 잠금은 화면에 섞여 보이는 중간색이 아니라 T 이전에는 이전 논리 색, T부터는 새 논리 색을 사용한다. 캐릭터 조명·위 배지·HUD 칩도 T에서 새 색으로 바뀐다.
- `Miss(FORBIDDEN)` 재추첨은 사전 예고가 없으므로 판정 스텝에 논리 색을 즉시 교체한다. 그 순간의 이전 화면을 시작 프레임으로 잡아 새 색까지 1초 동안 교차 페이드하고 해당 칸 타이머를 `5.300`으로 재설정한다.
- 페이드 중 같은 칸이 다시 재추첨되면 진행 중인 표시 전환을 취소하고 현재 합성색에서 최신 논리 색을 향한 새 1초 페이드를 시작한다. 판정과 타이머에는 중간색을 사용하지 않는다.
- 페이드 중에도 원 등장·링 수축·판정, 캐릭터 이동과 야구공 물리는 모두 계속된다. `Reduced Effects`에서도 이동·확대 없이 같은 1초 선형 불투명도 변화만 사용한다.

## 4. 타이밍 게임과 금지색

### 요구사항

- Match 영역의 무작위 장소에 비교적 큰 원이 생성된다.
- 원 색은 7색 중 무작위다.
- 원 바깥의 링이 원을 향해 줄어든다.
- 링이 원 테두리에 닿는 순간을 중심으로 정해진 유효 시간 안에 터치한다.
- 소리가 없어도 링과 원 테두리의 움직임만 보고 모든 타이밍을 판단할 수 있어야 한다.
- **캐릭터가 현재 서 있는 구역과 같은 색의 원만 터치 금지다.** Dodge의 다른 구역에 표시된 색이라는 이유만으로 금지하지 않는다.
- 색 전환 시각과 원의 등장·판정은 겹칠 수 있다. 상태 잠금과 같은 스텝의 이벤트 순서로 어느 색을 기준으로 했는지 결정한다.

예: 캐릭터가 빨간 구역에 있으면 빨간 원은 누르지 않고 파란 원은 정답 타이밍에 누른다. 파란 구역으로 이동하면 금지색이 파랑으로 바뀐다.

### 타이밍·판정 제안

- 원마다 생성 시각과 정답 시각을 갖고, 정답 시각에 링과 테두리가 일치한다.
- 첫 플레이 테스트는 아래 네 등급으로 판정한다. `시간차`는 실제 터치 시각과 링·테두리 일치 시각의 절댓값이다.

| 판정 | 시간차 | 처리 |
| --- | --- | --- |
| `Perfect` | 0~60ms | 최고 정확도 성공 |
| `Great` | 61~120ms | 높은 정확도 성공 |
| `Good` | 121~200ms | 유효 마진 안의 성공 |
| `Miss` | 200ms 초과 또는 허용색 원 미입력 | 실패 |

- 경계값 60ms, 120ms, 200ms는 각각 더 좋은 판정에 포함한다. 이 값들은 초기 튜닝값이며 플레이 테스트 후 조정한다.
- `Great`, `Good`, `Miss`에는 정답 시각 기준 `빠름` 또는 `늦음`을 보조 표시할 수 있다. 판정 등급 자체는 네 종류로 유지한다.
- 판정 구간이 시작되는 T−200ms에 캐릭터가 서 있는 구역 색으로 해당 원의 ‘터치/금지’ 상태를 잠근다. 판정 중 캐릭터가 다른 구역으로 이동해도 해당 원의 상태는 바뀌지 않는다.
- 금지색 원을 터치하면 시간 정확도와 관계없이 `Miss(금지색)`로 처리한다. 금지색 원을 판정 구간이 끝날 때까지 누르지 않으면 `Perfect`로 처리한다.
- 금지색 원을 터치한 `Miss(금지색)`에는 같은 프레임에 세 피드백을 실행한다. Match에서는 해당 원 옆에 `MISS / FORBIDDEN`을 표시하고, Dodge에서는 반려견의 480ms `forbidden-cry` 반응과 그 원에 저장된 `lockedZoneId` 한 칸의 즉시 색 재추첨을 시작한다. 캐릭터가 `ㅠoㅠ`처럼 잠깐 울지만 이동·충돌·차트·게임 시계는 멈추지 않고, 표시·충돌 크기도 바뀌지 않는다. 세부 포즈와 게임오버 연결은 [비주얼 디자인 플랜](visual-design.md)의 금지색 오입력 반응을 따른다.
- 시간 판정과 링 애니메이션은 같은 단조 증가 시간값을 사용한다. 프레임 수나 화면 주사율이 달라도 실제 유효 마진이 달라지지 않아야 한다.
- 시각적으로는 유효 구간에 들어오면 원 테두리를 잠깐 밝히는 등의 보조 표현을 둘 수 있다. 소리·진동은 판정에 필요한 정보가 아닌 선택 피드백이다.
- 터치 위치는 보이는 원 내부를 기본으로 하되 모바일에서는 원 바깥에 최대 8dp의 보이지 않는 여유 영역을 둔다. 가까운 원들의 여유 영역이 겹치면 실제 원 중심에 더 가까운 원을 선택한다. 원 크기는 최소 48dp 터치 영역을 확보해야 한다.
- 원이 생성된 뒤에도 금지 여부는 바뀔 수 있으며, 판정 구간 시작 순간에만 현재 캐릭터 구역 색을 읽어 최종 상태를 고정한다. 이 상태를 시각적으로 알아볼 수 있게 표시한다.
- 허용색을 200ms 유효 구간 안에 터치하면 해당 등급으로 성공 처리한다. 너무 이른 터치는 `Miss(빠름)`, 너무 늦은 터치나 미입력은 `Miss(늦음/놓침)`으로 기록한다.
- 터치 대상 원을 누르지 않으면 `Miss(놓침)`, 금지 대상 원을 누르지 않으면 자동 `Perfect`다. 따라서 모든 원은 정확히 하나의 네 단계 판정을 만든다.
- 판정된 원은 결과를 표시한 뒤 제거한다. 판정별 점수는 [점수와 리더보드](scoring-and-leaderboard.md), 생명 변화는 아래 규칙을 따른다.

### Match 생명 게이지

Match 게임에는 오락실 리듬게임 방식의 생명 게이지를 둔다. 초기 범위는 0~100이며 한 판을 **60**에서 시작한다. 모든 변화 후 0~100 범위로 제한하고, 0이 되면 Match 실패 상태가 된다.

`Good`은 생명을 올리거나 내리지 않는 중립 판정이다. `Great`과 `Perfect`는 생명을 회복하고, 두 판정이 연속될수록 회복량이 커진다.

| 연속 `Great/Perfect` 횟수 | `Great` 회복 | `Perfect` 회복 |
| ---: | ---: | ---: |
| 1~4 | +2 | +4 |
| 5~9 | +3 | +6 |
| 10~19 | +4 | +8 |
| 20 이상 | +5 | +10 |

- 회복 콤보는 `Great`과 `Perfect`만 연속 횟수에 포함한다. 두 판정은 서로 섞여도 하나의 콤보로 이어지며, 금지색 원을 올바르게 넘겨 얻은 자동 `Perfect`도 동일하게 포함한다.
- `Good`은 생명을 현상 유지하고 회복 콤보를 0으로 초기화한다. `Good`을 여러 번 이어도 생명 이득은 없다.
- `Miss`는 회복 콤보를 0으로 초기화한다.

`Miss`가 연속되면 생명 감소량이 빠르게 증가한다.

| 연속 `Miss` 횟수 | 생명 감소 |
| ---: | ---: |
| 1 | −8 |
| 2 | −12 |
| 3 | −16 |
| 4 이상 | −20 |

- 허용색 원의 빠름·늦음·놓침과 금지색 원 터치는 모두 `Miss` 연속 횟수에 포함한다.
- `Good`, `Great`, `Perfect`가 발생하면 `Miss` 연속 횟수를 0으로 초기화한다. 금지색 원의 올바른 미터치도 `Perfect`이므로 동일하다.
- 감소량은 1회당 최대 20으로 제한한다. 연속 `Miss` 횟수는 계속 기록하되 그 이상 감소량이 커지지는 않는다.
- 회복·감소 콤보는 생명 게이지만 바꾼다. 점수에는 별도의 `Good/Great/Perfect` 공통 점수 콤보를 적용한다.

게이지는 플레이 중 항상 보여주며 회복, 중립, 감소를 색뿐 아니라 움직임과 텍스트로도 구분한다. 수치는 초기 플레이 테스트용이며 생존 시간과 평균 판정 분포를 확인한 뒤 조정한다. Match 생명이 0이 되는 순간 전체 게임을 즉시 종료한다.

### 생성 제안

- 링까지 포함해 영역 밖으로 잘리지 않는 위치에 생성한다.
- 원은 플레이 시간 동안 계속 생성되며, 시간이 흐를수록 생성 간격이 짧아져 동시에 처리해야 하는 정보량이 늘어난다.
- 한 곡의 길이, BPM과 모든 원의 정답 시점은 차트 데이터로 고정한다. 런타임에서 생성 횟수를 무작위로 늘리거나 줄이지 않는다.
- 음악 적용 가능성을 위해 원의 **정답 시점**은 120 BPM, 4/4박자의 16분음표 격자에 둔다. 1박은 0.5초, 한 마디는 2초, 가장 작은 격자는 0.125초다.
- 쉬운 초반과 극난도 후반이 분명하게 나뉘도록 아래 밀도로 차트를 작성한다.

| 플레이 시간 | 정답 시점 간격 |
| --- | ---: |
| 0~30초 | 2.000초 |
| 30~60초 | 1.750초 |
| 60~90초 | 1.500초 |
| 90~120초 | 1.250초 |
| 120~145초 | 1.000초 |
| 145~165초 | 0.750초 |
| 165~180초 | **0.625초** |

- 최소 간격은 0.625초, 즉 16분음표 5칸이며 이후 더 짧아지지 않는다. 모든 정답 시점은 계속 16분음표 격자 위에 있어 정박과 엇박을 모두 사용할 수 있다.
- 5.300초 주기는 120 BPM의 박·16분음표 격자와 일부러 맞추지 않는다. 재추첨 위상이 음악과 원 정답 시점 사이를 계속 이동하며, 색 전환과 원의 등장·판정이 겹치는 경우를 정상 난이도와 운 요소로 허용한다.
- 원의 화면 등장 시점은 해당 정답 시점에서 링 수축 시간을 뺀 시각이다. 음악이 꺼져도 같은 내부 박자 시계와 시각 애니메이션을 사용한다.
- 링은 같은 시작 반지름에서 원 테두리까지 일정한 속도로 줄어든다. 시간이 흐르면 수축 시간이 짧아져 링의 실제 이동 속도가 빨라진다.

| 플레이 시간 | 링 수축 시간 | 120 BPM 기준 |
| --- | ---: | ---: |
| 0~60초 | 2.00초 | 4박 |
| 60~105초 | 1.75초 | 3.5박 |
| 105~140초 | 1.50초 | 3박 |
| 140~165초 | 1.25초 | 2.5박 |
| 165~180초 | **1.00초** | 2박 |

- 링 수축 시간은 최소 1.00초에서 더 짧아지지 않는다. 정답 간격이 수축 시간보다 더 빠르게 줄어들어 후반으로 갈수록 여러 원이 겹쳐 보인다.
- `Perfect / Great / Good / Miss`의 시간 마진은 링 속도와 관계없이 그대로 유지한다. 링이 빨라져도 `Good`의 ±200ms 유효 구간이 줄어들지는 않는다.
- 화면에 판정이 끝나지 않은 원은 최대 4개까지만 존재한다. 차트 검증 단계에서 모든 예정 원이 이 상한을 지키는지 확인한다.
- 차트를 만들 때 색 전환 주변 후보를 생략하지 않고 동시 원 4개 상한만 적용한다. 재생 중 원을 건너뛰거나 뒤로 미루지 않아 모든 플레이에서 판정 대상 수와 만점이 같다.
- 새 원의 본체와 터치 여유 영역은 기존 원과 겹치지 않게 무작위 위치를 추첨한다. 제한된 횟수 안에 자리를 찾지 못하면 미리 정의한 안전 위치를 사용하며 해당 원 자체를 생략하지 않는다.
- 생성 간격이 링 수축 시간보다 짧아지면 여러 원이 자연스럽게 동시에 보이도록 한다.
- 원 색과 안전 범위 안의 위치는 매 플레이 독립적으로 무작위 추첨한다. 같은 색과 위치 구역이 연속될 수 있다. 판정 대상 수는 고정되고 금지색의 올바른 미터치도 `Perfect`이므로 이론상 만점은 바뀌지 않는다.
- 매 판 생성한 난수 시드를 결과에 저장해 QA 재현과 부정 기록 확인에 사용한다. 경쟁 모드에서도 서로 다른 시드를 허용하며 무작위 변동을 게임의 일부로 취급한다.

첫 차트는 다음 규칙으로 고정 생성한다.

1. 첫 정답 시각은 2.000초다.
2. 현재 정답 시각이 속한 구간의 간격을 더해 다음 후보를 만든다.
3. 후보의 등장 시각은 `정답 시각 − 해당 구간 링 수축 시간`이다.
4. 판정 구간이 곡 끝을 넘는 후보는 만들지 않는다.

이 규칙의 첫 차트는 판정 대상 151개, 첫 정답 2.000초, 마지막 정답 179.625초다. 차트 JSON에는 생성 결과를 저장하고 런타임에서 다시 계산하지 않는다.

### 색 전환 경계

전환 직전·직후에도 새 원을 차트대로 생성한다. 화면에 남아 있는 원도 제거하지 않고 정상적으로 수축·판정하므로 색 전환과 여러 원이 겹치는 상황이 발생할 수 있다.

- 전환 전에 이미 터치/금지 상태가 잠긴 원은 배경색이 바뀌어도 잠긴 상태를 유지한다.
- 아직 상태가 잠기지 않은 원은 자신의 T−200ms 시점에 변경된 캐릭터 구역색을 읽는다.
- 동일한 시각의 처리 순서는 `기존 입력·잠긴 zone으로 판정 확정 → 점수·생명 반영 → 구조/정기 칸별 색 변경 → FORBIDDEN 대상 한 칸 재추첨·타이머 재설정 → 현재 캐릭터 구역색·조명·배지·HUD 갱신 → 새 원 생성 → 새 판정 상태 잠금`이다.
- 새 색은 직전 색과 같아도 다시 추첨된 정상 결과로 취급한다.

## 5. 음악과 디자인 인계

- 첫 경쟁 차트는 120 BPM, 4/4박자, 180초(90마디)로 고정한다. 240초 차트는 핵심 플레이 검증 후 `Endurance` 모드로 추가한다.
- 소리를 끄더라도 동일한 곡 타임라인과 차트가 진행된다. 화면만으로 생성, 접근, 성공 시점, 성공·실패 결과를 모두 알아볼 수 있어야 한다.
- 설정에는 `음악 켜기/끄기`를 두고 기본값은 켜짐으로 한다. 음악을 끄면 배경 음악만 음소거하며 차트 시간, 판정, 점수와 난이도는 바뀌지 않는다.
- 음악 설정은 기기에 저장하고 시작 화면과 일시정지 화면에서 변경할 수 있다. 효과음과 진동은 별도 설정으로 유지한다.
- 정답 시각은 곡의 정박·엇박에 배치한다. 5.300초 색 변경 주기는 음악 BPM과 독립적으로 유지해 전환 위상이 반복적으로 고정되지 않게 한다.
- 음악 재생 위치가 게임 판정 시계를 대신하지 않으며, 지연이나 음소거가 시각 판정을 바꾸지 않게 한다.
- 판정은 곡 재생 장치가 아니라 게임의 단조 증가 시계를 기준으로 계산하고, 기기별 오디오 지연을 보정할 수 있어야 한다.
- 음악 방향은 Toothless 춤 밈을 연상시키는 경쾌하고 장난스러운 레트로 댄스 에너지다. 기존 곡의 멜로디·편곡·음원을 복제하거나 샘플링하지 않고 완전히 새로운 선율과 편곡을 만든다.
- 캐릭터·점·링·화면의 시각 디자인과 음악 제작은 별도 디자인 플랜으로 넘긴다.
- 디자인 제안: 현재 금지색은 Match 원의 중심 기호, 캐릭터 바로 위 배지와 공통 HUD 칩에서 항상 확인할 수 있게 한다. Dodge 바닥에는 해당 구역색의 Match 문양 하나만 크게 새기고 반복 패턴·색 이름·다른 음영은 두지 않는다. 모든 배경 위에서 캐릭터와 야구공이 먼저 읽혀야 한다.

## 6. 한 판의 종료와 상태 처리

- Dodge 점과 충돌하거나 Match 생명이 0이 되면 즉시 게임오버다.
- 180초 차트가 끝날 때까지 두 실패 조건을 피하면 클리어하고 최종 점수를 기록한다.
- 게임오버와 클리어 모두 생존 시간, Dodge 점수, Match 점수, 판정 수, 최대 콤보와 난수 시드를 결과에 남긴다.
- 일시정지 중에는 게임 시계와 음악을 함께 멈춘다. 앱이 백그라운드로 이동하거나 포커스를 잃으면 자동 일시정지한다.
- 재개 시 3초 카운트다운 뒤 같은 게임 시각에서 계속한다. 판정 구간 안에서 중단되었으면 해당 원을 다시 보여주고 남은 시간을 이어간다.
- 실시간 멀티플레이는 후속 범위이며 첫 경쟁은 비동기 리더보드다.

## 7. 플레이 테스트 조정 대상

점·캐릭터 크기, 점 속도와 개수, 판정 마진, 생명 변화량, 콤보 배율은 첫 구현 기준선으로 채택한다. QA 결과에 따라 값은 바꿀 수 있지만 변경 시 `ruleset_version`을 올리고 기존 리더보드와 분리한다.
