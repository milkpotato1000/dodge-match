# Dodge Match 기술 설계

- 작성일: 2026-09-16
- 상태: 첫 구현 기준선
- 제품 규칙: [동시 플레이 게임 기획](../planning/gameplay.md)

## 플랫폼과 런타임

- 첫 구현은 TypeScript, Vite와 Phaser 4 계열을 사용하는 웹/PWA로 제작한다.
- 단일 코드베이스로 모바일 브라우저와 PC 브라우저를 지원한다.
- 논리 화면은 1600×900 가로 16:9이며 `FIT` 방식으로 화면 안에 맞춘다. 남는 영역은 레터박스로 처리하고 게임 비율을 늘이지 않는다.
- 목표 성능은 지원 기기에서 60fps다. 게임 판정은 렌더 프레임 수와 분리한다.
- 첫 지원 범위는 최신 주요 iOS Safari, Android Chrome과 데스크톱 Chrome/Edge다.

Phaser는 캔버스/WebGL 렌더링, 포인터 기반 마우스·터치 입력, 멀티터치 포인터, 화면 스케일링과 Web Audio 재생을 담당한다. 접근 가능한 이름 입력과 설정 UI는 HTML 오버레이를 사용할 수 있다.

## 화면과 상태

게임은 다음 상태를 갖는다.

1. `Boot`: 자산과 차트 로드
2. `Setup`: 플레이어 이름, 좌우 배치, 음악 켜기/끄기, 음량과 오디오 오프셋 설정
3. `Countdown`: 입력 잠금 상태의 3초 시작 안내
4. `Playing`: Dodge와 Match 동시 실행
5. `Paused`: 게임 시계와 오디오 동시 정지
6. `Result`: 클리어/실패 사유, 점수와 판정 통계 표시
7. `Leaderboard`: 로컬 또는 온라인 순위 표시

`Playing`은 `dodge_collision`, `match_depleted`, `chart_complete` 중 하나의 원인으로만 종료한다. 첫 두 원인은 게임오버, 마지막 원인은 클리어다.

## 핵심 모듈

| 모듈 | 책임 |
| --- | --- |
| `GameClock` | 일시정지 가능한 단조 증가 게임 시간 제공 |
| `ChartPlayer` | 정답 시각, 색 변경, 난이도 구간 이벤트 방출 |
| `DodgeSystem` | 캐릭터 이동, 점 생성·반사·충돌 |
| `ZoneResolver` | 경계 겹침 면적, 완충값과 현재 판정색 계산 |
| `MatchSystem` | 원 배치, 링 진행, 터치/금지 상태 고정과 판정 |
| `HealthSystem` | 회복 콤보, Miss 연속 감소와 0 판정 |
| `ScoreSystem` | 생존·판정·점수 콤보와 만점 계산 |
| `InputRouter` | 포인터·키보드를 각 게임 영역에 고정 할당 |
| `SeededRandom` | 색과 위치를 시드로 재현 가능한 무작위 추첨 |
| `ResultRecorder` | 결과와 통계 저장 |
| `LeaderboardRepository` | 로컬/온라인 순위 저장 구현 교체 지점 |

시뮬레이션은 60Hz 고정 스텝으로 진행한다. 긴 프레임 뒤에는 누적 시간을 제한하고, 캐릭터와 점 충돌은 이전·현재 위치 사이의 이동 구간을 포함해 검사하여 빠른 점이 캐릭터를 통과하는 현상을 막는다.

## 시간과 오디오

- 판정의 기준은 `GameClock`이며 오디오 재생 위치가 아니다.
- 차트 시작 시각에 사용자 오디오 보정값을 적용하되 시각 판정 시계는 바꾸지 않는다.
- 브라우저 오디오 활성화는 시작 버튼 입력에서 수행한다.
- 음소거 상태에서도 같은 `GameClock`과 차트가 진행된다.
- `musicEnabled`는 배경 음악 출력만 제어한다. 효과음·진동 설정과 분리하고 기기에 영구 저장한다.
- 음악 설정은 Setup과 Paused 상태에서 바꿀 수 있으며 Playing 복귀 시 현재 게임 시각에 맞춰 재생 또는 음소거한다.
- 백그라운드 전환, 창 포커스 상실과 화면 방향 변경 시 자동 일시정지한다.

## 차트 데이터 계약

차트는 버전이 있는 JSON 데이터로 관리한다.

| 필드 | 내용 |
| --- | --- |
| `chartId` | 곡·난이도를 식별하는 영구 ID |
| `chartVersion` | 판정 시점 변경 버전 |
| `rulesetVersion` | 점수·생명·난이도 규칙 버전 |
| `durationMs` | 첫 차트는 180000 |
| `bpm` / `timeSignature` | 첫 차트는 120 / 4·4 |
| `audioOffsetMs` | 음원의 첫 박과 게임 시각 차이 |
| `targets[]` | 원 등장 시각, 정답 시각, 수축 시간 |
| `colorTransitions[]` | 구역 단계와 색 재추첨 시각 |
| `dodgeCurve[]` | 시각별 목표 점 개수와 속도 |
| `maxScore` | 모든 판정을 Perfect로 완료한 계산값 |

차트 검증기는 정답 시각의 박자 격자, 색 변경 전후 보호 구간, 동시 원 최대 4개, 곡 길이, 시간 오름차순과 계산된 만점을 검사해야 한다.

색과 위치는 차트에 직접 저장하지 않는다. 한 판 시작 시 생성한 `rngSeed`로 추첨하고 결과에 시드를 기록한다. 같은 시드와 차트·규칙 버전을 사용하면 동일한 판을 재현할 수 있어야 한다.

## 입력 계약

- 모바일 포인터가 시작한 영역이 역할을 결정한다. 포인터가 경계를 넘어도 역할은 유지한다.
- Dodge 포인터 하나와 Match 포인터들을 동시에 추적한다.
- PC의 Dodge 입력은 WASD와 방향키, Match 입력은 주 마우스 버튼이다.
- 설정·일시정지 버튼 입력은 게임 판정보다 우선하며, 일시정지 직후 기존 포인터 캡처를 해제한다.
- 브라우저 스크롤, 확대 제스처와 길게 누르기 메뉴는 게임 캔버스 안에서 차단한다.

## 구역색 판정 계약

- 구역 경계의 시각 마진은 총 2U지만 기하학적 색 구역 자체는 중앙 경계까지 이어진다.
- 캐릭터 중심이 마진 밖이면 중심 좌표로 구역을 결정한다.
- 마진 안에서는 반지름 2.25U의 판정 원과 인접 구역의 교차 면적을 계산한다.
- 후보 구역이 현재 구역보다 전체 판정 원 면적의 10% 이상 우세할 때만 현재 구역을 바꾼다.
- 상태 잠금, 색 변경과 입력이 같은 시뮬레이션 스텝에 있으면 차트의 이벤트 순서를 적용한다.
- `ZoneResolver` 결과는 Match 판정, 캐릭터 조명, HUD 칩이 함께 구독해 서로 다른 색을 표시하지 않게 한다.

## 캐릭터 자산 계약

- 원본 반려견 사진·영상은 공개 저장소 밖에서만 다룬다.
- 승인된 파생 자산은 투명 PNG 마스터와 상태별 스프라이트로 버전 관리한다.
- 렌더 이미지와 충돌 원을 분리하여 자산 교체가 게임 난이도를 바꾸지 않게 한다.
- 첫 구현은 `docs/design/characters/player-dog-idle-v1.png`와 `player-dog-state-sheet-v1.png`를 dev 자산 경로로 복사해 사용한다.
- Pip은 반려견 자산 로드 실패 시에만 같은 표시·충돌 크기로 나타나는 개발 폴백이다.

## 저장과 리더보드

첫 개발은 `LocalLeaderboardRepository`로 설정, 최고 기록과 최근 기록을 기기에 저장한다. 게임 플레이 검증 후 동일 인터페이스의 온라인 구현을 추가한다.

온라인 기록은 `chartId + chartVersion + rulesetVersion` 단위로 순위를 분리한다. 제출 데이터에는 플레이어 이름, 점수 구성, 판정 수, 생존 시간, 종료 사유와 `rngSeed`를 포함한다. 클라이언트 점수만 신뢰하는 초기 서비스에는 조작 가능성이 있으므로 공개 경쟁 단계에서는 서버 재계산 또는 플레이 이벤트 검증을 추가한다.

## 검증 목표

- 60Hz와 120Hz 화면에서 같은 입력 시 같은 판정 결과
- 음소거와 오디오 재생에서 같은 차트·입력 결과
- 좌우 교환 후 규칙과 좌표만 대칭이며 난이도 동일
- 음악 켜기/끄기 전후 같은 입력의 판정·점수 동일
- 경계 마진에서 미세 이동 시 10% 완충값 안에서는 판정색이 유지됨
- 저장한 시드로 색·위치 완전 재현
- 백그라운드 복귀 후 시간 점프와 자동 Miss 없음
- 지원 화면 비율에서 원 터치 영역, 생명 게이지와 카운트다운이 잘리지 않음
